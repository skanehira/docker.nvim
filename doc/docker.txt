1. Introduction                                          *docker-introduction*

docker.nvim operates Docker from Neovim. In addition to containers, images,
volumes and networks, it lists and operates the services of every docker
compose project at once. Whichever directory Neovim is opened in, all the
compose projects on the machine appear in a single list.

Lists subscribe to `docker events` and refresh themselves. When you start or
stop a container from another terminal, the list in Neovim catches up within
a second.

It has no runtime plugin dependencies.

==============================================================================
2. Requirements                                          *docker-requirements*

- Neovim 0.10 or later (uses `vim.system`)
- The `docker` command on PATH
- `:Docker services` needs the `docker compose` subcommand
  (without it that list is not opened and a message is shown; the other four
  lists still work)
- Supported platforms are macOS and Linux

When the required version is not met, `setup()` notifies you and disables the
plugin without registering the command and the keymaps.

==============================================================================
3. Commands                                                  *docker-commands*

                                                                     *:Docker*
:Docker {kind}
    Opens a resource list. {kind} is one of the following.

        containers      containers
        images          images
        volumes         volumes
        networks        networks
        services        compose services (all projects combined)

    Without an argument it shows the usage.

Lua API~
                                                              *docker.setup()*
require("docker").setup({opts})
    Applies the configuration. See |docker-configuration|.

                                                               *docker.open()*
require("docker").open({kind})
    Opens a list. The same as `:Docker {kind}`.

                                                              *docker.close()*
require("docker").close()
    Closes every open list.

<Plug> mappings~
                                                   *<Plug>(docker-containers)*
The following mappings are exposed. Map them to any key you like. >lua
    vim.keymap.set("n", "<leader>dc", "<Plug>(docker-containers)")
<
    <Plug>(docker-containers)
    <Plug>(docker-images)
    <Plug>(docker-volumes)
    <Plug>(docker-networks)
    <Plug>(docker-services)

4. Keymaps                                                    *docker-keymaps*

Keys are set only in the buffer of the list. They never take over the keys of
other buffers.

Common to every list view~
                                                       *docker-keymaps-common*
    <CR>        show the details (docker inspect)
    R           reload the list (also resumes a dropped event subscription)
    <Tab>       switch to the list of another resource
    <C-f>       filter by the displayed values (`/` stays Neovim's search)
    ?           show the keys available in that view
    q           close

In a list, <C-d> / <C-u> / <C-b> work as Neovim's own scrolling (only <C-f>
is bound to filtering).

The <C-f> filter is a case-insensitive substring match against the values of
all displayed columns, and a row is kept when any one of them matches. In the
container list it is kept when the text is contained in NAME / IMAGE /
STATUS / PORTS / PROJECT / SERVICE. Confirming the prompt
(`絞り込み (空で解除): `) while it is empty clears the filter. When nothing
matches, the view falls back to the empty text of that kind, such as
`コンテナがありません`, so tell whether a filter is active by the text you
typed.

Lists do not wrap. A value too long for the window is cut off at the right
edge, so scroll right with zl or l to read it. The header scrolls with the
rows, so you can always tell which column you are looking at.

Container list~
                                                    *docker-keymaps-container*
    u           start
    d           stop
    r           restart
    <C-k>       kill
    p           pause
    P           unpause
    a           open a shell in the container
    e           run a command in the container
    t           follow the logs
    D           delete (with confirmation)
    ct          copy from the host into the container
    cf          copy from the container to the host
    E           edit a file inside the container
    <C-o>       open a published port in the browser
    gd          go to the image of this container

Image list~
                                                        *docker-keymaps-image*
    r           open a shell in a throwaway container
    D           delete (with confirmation)
    gd          go to the containers using this image

Volume and network lists~
                              *docker-keymaps-volume* *docker-keymaps-network*
    D           delete (with confirmation)

compose service list~
                                                      *docker-keymaps-service*
    u           start the service
    d           stop the service
    r           restart the service
    t           follow the logs of the service
    U           start the whole project of the row
    D           remove the whole project of the row (with confirmation)
    gd          go to the containers of this service

The list has the four columns PROJECT / SERVICE / STATUS / CONTAINER, sorted
by project name. An operation targets the project of the row under the cursor,
so you can stop a service of blog while Neovim stays opened in the directory
of shop. Services with the same name (shop/web and blog/web) are separate rows
as long as the projects differ.

D (removing the project) is the only operation that asks for confirmation.
u / d / r / U run at the moment you press them, so check the PROJECT column
first when several projects are listed.

When there is no compose project at all, the list shows the single line
`compose プロジェクトがありません`.

Bulk delete~
                                                          *docker-bulk-delete*
In the container, image, volume and network lists, select a range in Visual
mode and press D to delete the selected rows at once. The rest still run when
some of them fail, and the failures are reported together (the D of the
compose service list removes a project, so it is out of scope).

When a list closes~
                                                           *docker-auto-close*
Besides q, a list also closes when the focus moves to a window that is not a
float. This keeps the list from lingering behind the log opened with t, the
shell entered with a, or the file inside a container opened with E. It stays
when the destination is a float, so it survives the details (<CR>), the help
(?) and another list (gd / <Tab>), as well as floats of other plugins and the
input field of an environment that implements vim.ui.input as a float.

5. Configuration                                        *docker-configuration*

>lua
    require("docker").setup({
      debug = false,
      keymaps = {
        common = { close = "<Esc>" },
        container_list = {
          start = "s",
          delete = false,
        },
      },
    })
<
                                                            *docker-opt-debug*
debug ~
    Default: `false`

    Notifies the docker commands that were run, their exit codes, and the
    number of lines that failed to parse.

                                                          *docker-opt-keymaps*
keymaps ~
    Given per view kind as "action name -> key". The view kinds are the
    following.

        common          common to every list view
        container_list  container list
        image_list      image list
        volume_list     volume list
        network_list    network list
        service_list    compose service list

    Anything not given keeps its default. Passing `false` as the key removes
    that binding. The same key can be bound to a different action per view
    kind (`r` restarts in the container list and runs a throwaway container
    in the image list).

    An unknown view kind or action name is ignored per entry, with a warning.

                                                           *docker-highlights*
Highlights~
    Column headers are drawn with DockerHeader, and the STATUS column with
    the following groups depending on the state.

        DockerHeader            column header
        DockerStatusRunning     running
        DockerStatusExited      exited
        DockerStatusPaused      paused
        DockerStatusCreated     created
        DockerStatusRestarting  restarting
        DockerStatusDead        dead
        DockerStatusNone        service without a container
        DockerStatusUnknown     any state none of the above matches

    DockerStatusUnknown links to `Normal` by default, so it keeps the normal
    text color unless you set it. Include it as well when you replace the
    whole color scheme.

    All of them are defined with `default`, so a group you define beforehand
    wins.
>lua
    vim.api.nvim_set_hl(0, "DockerHeader", { fg = "#7aa2f7", bold = true })
<

6. Behavior                                                  *docker-behavior*

Deletion~
                                                      *docker-behavior-delete*
    Deletion never passes `-f`. Deleting a running container is left for
    docker to reject, and its error is shown as it is. Stop it first, then
    delete it.

Operations whose precondition is not met~
                                                       *docker-behavior-guard*
    An operation whose precondition is not met, such as <C-k> on a stopped
    container, warns without calling docker.

Duplicated operations~
                                                   *docker-behavior-exclusive*
    The same operation on the same target runs one at a time. A row being
    operated on is marked with `(実行中)`.

Child processes~
                                                        *docker-behavior-jobs*
    Child processes started for logs and shells are tracked in a ledger and
    always stopped on `:qa`.

When the event subscription drops~
                                                      *docker-behavior-events*
    Resubscription is retried up to five times with a growing wait. On
    recovery the list is reloaded to make it consistent again. After five
    failures it asks you to refresh manually with `R`.

What compose operations target~
                                                     *docker-behavior-compose*
    The service list covers every compose project that exists, and each
    operation names the project of the row under the cursor with `-p`. The
    current directory is fixed at the moment the list is opened, and is used
    to merge the compose project of that directory into the list (one that
    has never been started, and so cannot be found any other way because it
    has no container) and to locate the compose file of that project. When
    the project you want is missing from the list, reopen the list in its
    directory, or start it once and it will be listed from anywhere after
    that.

Projects whose compose file cannot be located~
                                              *docker-behavior-compose-nopath*
    For a project whose compose file location appears neither in the labels
    of its containers nor in the output of `docker compose ls`, only the
    services that have a container are listed. Starting (u / U) needs the
    definition in the compose file itself, so it warns without calling
    docker. Stopping, restarting, removing and logs only need the project
    name, so they run as usual. The four columns do not tell which rows these
    are, so identify them by the warning you get when pressing u.
    When the location is known but that directory has been moved or deleted,
    it runs without warning and shows the error from docker as it is.

When the compose file cannot be read~
                                               *docker-behavior-compose-error*
    The list opens even when the compose file of the current directory is
    broken. The error from docker is notified as a warning exactly once, and
    is not repeated every time an event reloads the list.
