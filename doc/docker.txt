1. 概要                                                  *docker-introduction*

docker.nvim は Neovim から Docker を操作するプラグインです。コンテナ・イメージ・
ボリューム・ネットワークに加え、docker compose のサービスを全プロジェクト
まとめて一覧・操作できます。どのディレクトリで Neovim を開いていても、その
マシンにある compose プロジェクトが 1 つの一覧に並びます。

一覧は `docker events` を購読して自動更新されます。別のターミナルでコンテナを
起動・停止しても、Neovim 側の一覧が 1 秒以内に追従します。

ランタイムのプラグイン依存はありません。

==============================================================================
2. 前提                                                  *docker-requirements*

- Neovim 0.10 以上 (`vim.system` を使用)
- `docker` コマンドが PATH 上にあること
- `:Docker services` には `docker compose` サブコマンドが必要
  (無い場合は一覧を開かずに通知します。他の 4 つの一覧はそのまま使えます)
- 対応プラットフォームは macOS と Linux

要求バージョンを満たさない場合、`setup()` がメッセージを通知し、コマンドと
キーマップを登録せずに機能を無効化します。

==============================================================================
3. コマンド                                                  *docker-commands*

                                                                      *:Docker*
:Docker {kind}
    リソースの一覧を開きます。{kind} は次のいずれかです。

        containers      コンテナ
        images          イメージ
        volumes         ボリューム
        networks        ネットワーク
        services        compose サービス (全プロジェクトを統合)

    引数を省略した場合は使い方を表示します。

Lua API~
                                                          *docker.setup()*
require("docker").setup({opts})
    設定を取り込みます。|docker-configuration| を参照してください。

                                                           *docker.open()*
require("docker").open({kind})
    一覧を開きます。`:Docker {kind}` と同じです。

                                                          *docker.close()*
require("docker").close()
    開いている一覧をすべて閉じます。

<Plug> マッピング~
                                             *<Plug>(docker-containers)*
次のマッピングを公開しています。好きなキーへ割り当てられます。 >lua
    vim.keymap.set("n", "<leader>dc", "<Plug>(docker-containers)")
<
    <Plug>(docker-containers)
    <Plug>(docker-images)
    <Plug>(docker-volumes)
    <Plug>(docker-networks)
    <Plug>(docker-services)

4. キーマップ                                                 *docker-keymaps*

キーは一覧のバッファにだけ設定されます。他のバッファの操作は奪いません。

全一覧ビュー共通~
                                                       *docker-keymaps-common*
    <CR>        詳細 (docker inspect) を表示する
    R           一覧を取り直す (切れていたイベント購読も再開する)
    <Tab>       別のリソースの一覧へ切り替える
    <C-f>       表示中の値で絞り込む (`/` は Neovim 本来の検索のまま)
    ?           そのビューで有効なキーの一覧を表示する
    q           閉じる

一覧では <C-d> / <C-u> / <C-b> が Neovim 本来のスクロールとして使えます
(<C-f> だけは絞り込みに割り当てています)。

一覧は折り返しません。値が長くてウィンドウに収まらないときは右端で切れる
ので、zl や l で右へスクロールして読みます。見出しもスクロールに合わせて
動くので、どの列を見ているかは常に分かります。

コンテナ一覧~
                                                    *docker-keymaps-container*
    u           起動する
    d           停止する
    r           再起動する
    <C-k>       強制終了する
    p           一時停止する
    P           一時停止を解除する
    a           コンテナ内でシェルを開く
    e           コンテナ内でコマンドを実行する
    t           ログを追う
    D           削除する (確認あり)
    ct          ホストからコンテナへコピーする
    cf          コンテナからホストへコピーする
    E           コンテナ内のファイルを編集する
    <C-o>       公開ポートをブラウザで開く
    gd          このコンテナのイメージへ移動する

イメージ一覧~
                                                       *docker-keymaps-image*
    r           使い捨てコンテナでシェルを開く
    D           削除する (確認あり)
    gd          このイメージを使うコンテナへ移動する

ボリューム・ネットワーク一覧~
    D           削除する (確認あり)

compose サービス一覧~
                                                     *docker-keymaps-service*
    u           サービスを起動する
    d           サービスを停止する
    r           サービスを再起動する
    t           サービスのログを追う
    U           行のプロジェクト全体を起動する
    D           行のプロジェクト全体を破棄する (確認あり)
    gd          このサービスのコンテナへ移動する

一覧は PROJECT / SERVICE / STATUS / CONTAINER の 4 列で、プロジェクト名の昇順
に並びます。操作の対象はカーソル行のプロジェクトなので、shop のディレクトリで
Neovim を開いたまま blog のサービスを停止できます。同名のサービス (shop/web と
blog/web) は、プロジェクトが違えば別の行として扱われます。

確認を挟むのは D (プロジェクトの破棄) だけです。u / d / r / U は押した時点で
実行されるため、複数プロジェクトが並ぶ一覧では PROJECT 列を確かめてから押して
ください。

compose プロジェクトが 1 つも無いときは `compose プロジェクトがありません` の
1 行を出します。

一括削除~
コンテナ・イメージ・ボリューム・ネットワークの一覧で、Visual モードで範囲を
選んでから D を押すと、選択した行をまとめて削除できます。一部が失敗しても他は
実行され、失敗した分がまとめて通知されます (compose サービス一覧の D は
プロジェクトの破棄なので対象外です)。

一覧を閉じる契機~
q のほかに、一覧の外のウィンドウへフォーカスが移ったときにも一覧は閉じます。
t でログを開いたとき、a でシェルに入ったとき、E でコンテナ内のファイルを
開いたときに、一覧がその裏へ残り続けないようにするためです。詳細 (<CR>)・
ヘルプ (?)・別の一覧 (gd / <Tab>) へ移ったときは閉じません。

5. 設定                                                 *docker-configuration*

>lua
    require("docker").setup({
      debug = false,
      keymaps = {
        common = { close = "<Esc>" },
        container_list = {
          start = "s",
          delete = false,
        },
      },
    })
<
                                                             *docker-opt-debug*
debug ~
    既定値: `false`

    実行した docker コマンドと終了コード、解析に失敗した行数を通知します。

                                                           *docker-opt-keymaps*
keymaps ~
    ビュー種別ごとに「アクション名 -> キー」で指定します。ビュー種別は次の
    とおりです。

        common          全一覧ビュー共通
        container_list  コンテナ一覧
        image_list      イメージ一覧
        volume_list     ボリューム一覧
        network_list    ネットワーク一覧
        service_list    compose サービス一覧

    指定しなかった項目は既定のままです。キーに `false` を渡すと、その割り当てを
    外せます。同じキーをビュー種別ごとに別の操作へ割り当てられます (コンテナ
    一覧の `r` は再起動、イメージ一覧の `r` は使い捨て実行)。

    未知のビュー種別やアクション名は、その項目だけ無視して警告します。

                                                          *docker-highlights*
配色~
    列見出しは DockerHeader、STATUS 列は状態ごとに次のグループで描きます。

        DockerHeader            列見出し
        DockerStatusRunning     実行中
        DockerStatusExited      終了済み
        DockerStatusPaused      一時停止
        DockerStatusCreated     作成済み
        DockerStatusRestarting  再起動中
        DockerStatusDead        異常終了
        DockerStatusNone        コンテナが無いサービス

    いずれも `default` 指定なので、先に定義しておけばそちらが優先されます。
>lua
    vim.api.nvim_set_hl(0, "DockerHeader", { fg = "#7aa2f7", bold = true })
<

6. 動作の約束                                                *docker-behavior*

削除~
    削除に `-f` は付けません。実行中コンテナの削除は docker に拒否させ、その
    エラーをそのまま提示します。先に停止してから削除してください。

前提を満たさない操作~
    停止中のコンテナへの `<C-k>` のように前提を満たさない操作は、docker を
    呼ばずに警告します。

重複した操作~
    同じ対象への同じ操作は同時に 1 つまでです。実行中の行には `(実行中)` が
    付きます。

子プロセス~
    ログやシェルで起動した子プロセスは台帳で追跡し、`:qa` で必ず停止します。

イベント購読が切れたとき~
    待機時間を延ばしながら最大 5 回まで再購読を試みます。回復したときは一覧を
    取り直して整合させます。5 回失敗した場合は `R` による手動更新を促します。

compose の対象~
    サービス一覧は存在するすべての compose プロジェクトを対象とし、各操作は
    カーソル行のプロジェクトを `-p` で名指しして実行します。カレントディレクト
    リは一覧を開いた時点で固定し、そのディレクトリの compose プロジェクト
    (まだ一度も起動しておらず、コンテナが無いために他の経路では見つからない
    もの) を一覧へ合流させることと、そのプロジェクトの compose ファイルの場所
    を決めることに使います。目当てのプロジェクトが一覧に出てこないときは、
    そのディレクトリで開き直すか、一度起動すれば以後は場所に関係なく並びます。

compose ファイルの場所が分からないプロジェクト~
    コンテナのラベルにも `docker compose ls` の出力にも compose ファイルの場所
    が現れないプロジェクトでは、コンテナが実在するサービスだけを一覧に出しま
    す。起動 (u / U) は compose ファイルの定義そのものが要るため、docker を呼
    ばずに警告します。停止・再起動・破棄・ログはプロジェクト名の名指しだけで
    済むので、そのまま実行できます。どの行がこれに当たるかは 4 列の表示からは
    分からないため、u を押したときの警告で判別してください。
    場所は分かるが、そのディレクトリが移動・削除されている場合は警告せずに実
    行し、docker のエラーをそのまま表示します。

compose ファイルが読めないとき~
    カレントディレクトリの compose ファイルが壊れていても一覧は開きます。
    docker のエラーをそのまま警告として 1 回だけ通知し、イベントで一覧を取り
    直すたびに同じ警告を繰り返すことはありません。
