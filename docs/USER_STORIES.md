# ユーザーストーリー

- 種別: ユーザーストーリー
- 対象: docker.nvim (Neovim 用 Docker クライアントプラグイン)
- 作成日: 2026-07-29

## プロダクト概要

Neovim から離れずに Docker のコンテナ・イメージ・ボリューム・ネットワーク、および docker compose のサービス／プロジェクトを操作できるプラグイン。アーキテクチャは [k8s.nvim](https://github.com/skanehira/k8s.nvim)、デフォルトキーマップは [denops-docker.vim](https://github.com/skanehira/denops-docker.vim)、compose の扱いは [lazydocker](https://github.com/jesseduffield/lazydocker) を参考にする。

対象 Neovim バージョン: 0.10 以上（非同期実行に `vim.system()` を使うため）。

## ユーザータイプ

| タイプ | 説明 |
| --- | --- |
| Neovim 開発者 | 日常の開発を Neovim 上で行い、compose でローカル環境を立ち上げている開発者。ターミナルを切り替えて `docker ps` / `docker compose logs` を叩く往復をなくしたい |

単一ユーザータイプ。プラグイン利用者と設定者は同一人物であり、管理者・運用者といった別ロールは存在しない。

## ストーリー一覧

### Must（必須）

#### US-001: コンテナ一覧を見る

- **As a** Neovim 開発者
- **I want to** 実行中・停止中のコンテナを一覧で見る
- **So that** ターミナルに切り替えず今の環境の状態を把握できる

**受け入れ基準**:

- [ ] Given docker が起動している When `:Docker containers` を実行する Then 全コンテナ（停止中含む）が NAME / IMAGE / STATUS / PORTS / PROJECT / SERVICE のカラムで一覧表示される
- [ ] Given コンテナが compose 由来である When 一覧を表示する Then PROJECT 列に `com.docker.compose.project`、SERVICE 列に `com.docker.compose.service` の値が表示される
- [ ] Given compose 由来でないコンテナがある When 一覧を表示する Then PROJECT / SERVICE 列は空欄で表示され、行自体は省略されない
- [ ] Given コンテナが 1 つも存在しない When 一覧を表示する Then 空である旨のメッセージが表示され、エラーにはならない
- [ ] Given 一覧ビューを開いている When 一覧バッファで文字を入力する Then バッファは編集されない（`buftype=nofile` かつ `nomodifiable`）

**エピック**: EP-1

---

#### US-002: コンテナのライフサイクルを操作する

- **As a** Neovim 開発者
- **I want to** 一覧上のコンテナを start / stop / restart / kill する
- **So that** 環境の起動・停止をエディタ内で完結できる

**受け入れ基準**:

- [ ] Given 停止中のコンテナにカーソルがある When `u` を押す Then そのコンテナが起動し、一覧の STATUS が running に更新される
- [ ] Given 実行中のコンテナにカーソルがある When `d` を押す Then そのコンテナが停止し、一覧の STATUS が exited に更新される
- [ ] Given 実行中のコンテナにカーソルがある When `r` を押す Then そのコンテナが再起動し、STATUS が running のまま稼働時間表示（`Up X seconds`）がリセットされる
- [ ] Given 停止中のコンテナにカーソルがある When `<C-k>`（kill）を押す Then 実行中でない旨のエラーメッセージが表示され、操作は実行されない
- [ ] Given docker 側で失敗する状況にある（例: ホスト側ポートが他プロセスに占有されている） When `u` で start を実行する Then docker のエラーメッセージが通知され、一覧の STATUS は変更されない

**エピック**: EP-1

#### US-003: コンテナを削除する

- **As a** Neovim 開発者
- **I want to** 不要なコンテナを削除する
- **So that** 一覧を整理し、名前の衝突を避けられる

**受け入れ基準**:

- [ ] Given 停止中のコンテナにカーソルがある When `<C-d>` を押す Then 削除確認のプロンプトが表示される
- [ ] Given 削除確認のプロンプトが表示されている When `y` を入力する Then コンテナが削除され、一覧から消える
- [ ] Given 削除確認のプロンプトが表示されている When `n` または空入力で確定する Then コンテナは削除されず一覧も変化しない
- [ ] Given 実行中のコンテナにカーソルがある When `<C-d>` を押して確認に `y` と答える Then 実行中である旨の docker のエラーが通知され、コンテナは削除されない（強制削除は行わない）

**エピック**: EP-1

- [ ] Given 停止中のコンテナにカーソルがある When `a` を押す Then 実行中でない旨のエラーが表示され、ターミナルは開かない

- [ ] Given コンテナに使用中のイメージにカーソルがある When `<C-d>` を押して確認に `y` と答える Then docker のエラーメッセージ（使用中である旨）が通知され、一覧は変化しない

#### US-008: compose サービス一覧を見る

- **As a** Neovim 開発者
- **I want to** カレントディレクトリの compose プロジェクトのサービスを一覧で見る
- **So that** どのサービスがどの状態かを lazydocker のように一望できる

**受け入れ基準**:

- [ ] Given compose プロジェクトのディレクトリで Neovim を開いている When `:Docker services` を実行する Then SERVICE / STATUS / CONTAINER のカラムでサービスが一覧表示され、状態は running / exited / none のいずれかで表示される
- [ ] Given compose に定義されているがコンテナが起動していないサービスがある When 一覧を表示する Then そのサービスが状態 `none` として表示される
- [ ] Given compose プロジェクト外のディレクトリにいる When サービス一覧を開く Then compose プロジェクト内ではない旨のメッセージが表示され、エラーで終了しない
- [ ] Given compose ファイルの記述が不正なディレクトリにいる When サービス一覧を開く Then compose のエラーメッセージが表示され、compose プロジェクト外とは区別される
- [ ] Given `COMPOSE_FILE` 環境変数や compose のオーバーライドファイルでプロジェクトが構成されている When サービス一覧を開く Then `docker compose` CLI が解決したのと同じサービス集合が表示される（compose ファイルの探索規則はプラグイン側で実装せず CLI に委ねる）

**エピック**: EP-3

#### US-009: サービス単位で操作する

- **As a** Neovim 開発者
- **I want to** サービス単位で up / stop / restart し、ログを見る
- **So that** 特定サービスだけを再起動して開発サイクルを回せる

**受け入れ基準**:

- [ ] Given 状態が none のサービスにカーソルがある When `u` を押す Then そのサービスが `docker compose up -d <service>` で起動し、状態が running に更新される
- [ ] Given running のサービスにカーソルがある When `d` を押す Then そのサービスが停止し、状態が exited に更新される
- [ ] Given running のサービスにカーソルがある When `r` を押す Then そのサービスのコンテナが再起動し、状態が running のまま稼働時間表示がリセットされる
- [ ] Given running のサービスにカーソルがある When `t` を押す Then そのサービスのログが follow モードで開く
- [ ] Given 状態が none のサービスにカーソルがある When `t` を押す Then コンテナが無い旨のメッセージが表示され、ターミナルは開かない

**エピック**: EP-3

#### US-010: compose プロジェクト単位で起動・停止する

- **As a** Neovim 開発者
- **I want to** プロジェクト全体を up -d / down する
- **So that** 開発環境の一括起動・一括破棄ができる

**受け入れ基準**:

- [ ] Given compose プロジェクトのディレクトリにいる When サービス一覧で `U` を押す Then プロジェクト全体が `docker compose up -d` で起動し、一覧の各サービスのコンテナが作成・起動される（処理を終えてすぐ終了するサービスは exited になり得る）
- [ ] Given プロジェクトが起動している When `D` を押して確認に `y` と答える Then プロジェクト全体が `docker compose down` で停止・破棄され、各サービスが none になる
- [ ] Given `D` の確認プロンプトが表示されている When `n` で答える Then プロジェクトは停止されない

**エピック**: EP-3

#### US-011: コンテナ一覧が自動で最新化される

- **As a** Neovim 開発者
- **I want to** 別ターミナルでの docker 操作もコンテナ一覧に自動で反映されるようにする
- **So that** 手動リフレッシュを意識せず現在の状態を見られる

**受け入れ基準**:

- [ ] Given コンテナ一覧を開いている When 別プロセスでコンテナを起動・停止する Then `docker events` の受信から 1 秒以内に該当行の STATUS が更新される（手動操作不要）
- [ ] Given コンテナ一覧を開いている When 別プロセスでコンテナを新規作成・削除する Then 一覧に行が追加・削除される
- [ ] Given 一覧を開いている When 短時間に複数のイベントが連続して発生する Then 再描画はデバウンスされて 1 回にまとめられ、カーソル位置が保持される
- [ ] Given イベント購読が動作している一覧ビューを開いている When ビューを破棄する（`q` / `:bd` / タブを閉じる のいずれか） Then `docker events` の購読ジョブが終了し、孤児プロセスが残らない
- [ ] Given 一覧ビューを開いたまま Neovim を終了する When `:qa` を実行する Then 購読ジョブとターミナルジョブがすべて終了し、孤児プロセスが残らない
- [ ] Given イベント購読中に docker デーモンが再起動してストリームが切断された When 切断を検知する Then 切断した旨が通知され、自動で再購読を試みる（一定回数失敗したら手動更新を促すメッセージを表示する）

**エピック**: EP-4

- [ ] Given イベント購読が切断された状態で一覧を開いている When `R` を押す Then 一覧が再取得されるとともに、イベント購読が再開される

**エピック**: EP-4

#### US-013: docker の操作中も Neovim を操作できる

- **As a** Neovim 開発者
- **I want to** docker コマンドの実行中も Neovim の編集操作を続けられる
- **So that** `docker compose up` のような数十秒かかる処理の待ち時間に作業を止めずに済む

- [ ] Given 一覧ビューを開く操作を行った When 初回のデータ取得が完了する前にキー入力する Then Neovim が固まらず、取得完了後に一覧が描画される

**エピック**: EP-4

#### US-014: docker が使えない状況が分かる

- **As a** Neovim 開発者
- **I want to** docker 未インストール・デーモン未起動・権限不足を明確なメッセージで知る
- **So that** プラグインの不具合と環境問題を切り分けられる

**受け入れ基準**:

- [ ] Given docker コマンドが PATH に無い When 一覧を開く Then docker が見つからない旨のメッセージが表示され、空ウィンドウは開かない
- [ ] Given docker デーモンが停止している When 一覧を開く Then デーモンに接続できない旨のメッセージが表示される
- [ ] Given docker ソケットへのアクセス権限が無い（`permission denied`） When 一覧を開く Then 権限が不足している旨のメッセージが表示され、デーモン未起動のメッセージとは区別される
- [ ] Given docker compose サブコマンドが使えない When サービス一覧を開く Then compose が利用できない旨のメッセージが表示され、コンテナ一覧など他の機能は引き続き使える

**エピック**: EP-4

- **As a** Neovim 開発者

#### US-020: イメージの詳細を確認する

#### US-023: コンテナ内のファイルを編集する

- **As a** Neovim 開発者
- **I want to** コンテナ内のファイルを Neovim で開いて編集し、保存でコンテナへ反映する
- **So that** コンテナ内に vim を入れずに設定を書き換えられる

**受け入れ基準**:

- [ ] Given コンテナにカーソルがある When `E` を押してコンテナ内のパスを入力する Then そのファイルの内容が `docker://<container>/<path>` という名前のバッファで開く
- [ ] Given 同じパスのファイルを別々のコンテナで開いた When 両方のバッファを開いている Then バッファ名が異なり、それぞれ対応するコンテナへ書き戻される
- [ ] Given コンテナ内ファイルのバッファを編集した When `:w` で保存する Then 変更がコンテナ内のファイルに反映され、完了メッセージが表示される
- [ ] Given コンテナ内で書き込みできないパス（読み取り専用 FS・権限不足）のバッファを編集した When `:w` で保存する Then docker のエラーメッセージが通知され、バッファは modified のまま保持される
- [ ] Given コンテナ内に存在しないパスを入力した When 編集を開始する Then ファイルが存在しない旨のメッセージが表示され、バッファは開かない

**エピック**: EP-7

### Won't（今回はやらない）

| ID | 内容 | 理由 |
| --- | --- | --- |
| WN-001 | Docker Hub のイメージ検索・pull | 今回のスコープ外（denops-docker.vim にはあるが優先度が低い） |
| WN-002 | カレントディレクトリ外の compose プロジェクトへの up/down 等の compose 操作 | lazydocker 同様、compose ファイルのパス解決が必要になるため見送る。該当コンテナ単体の操作は US-002 で可能 |
| WN-003 | Docker Swarm / Kubernetes 連携 | k8s.nvim の領域 |
| WN-004 | イメージのビルド（`docker build`） | ビルドコンテキストの指定 UI が必要になり、スコープが膨らむため |
| WN-005 | volume / network の作成 | 作成は compose か docker CLI で行うのが通常のため |
| WN-006 | `:checkhealth` による自己診断 | docker 未検出・権限不足は US-014 のメッセージで切り分けられるため |
| WN-007 | `:Docker` の引数なし起動とサブコマンド補完 | 今回はサブコマンドの明示指定のみ対応する |
| WN-008 | コンテナの CPU / メモリ使用率の表示 | コンテナごとに stats のストリームを張る必要があり、優先度に見合わないため後回しにする |

## 非機能要件

ストーリー横断で満たすべき制約。個別のストーリーに紐づかないものをここにまとめる。

| ID | 要件 | 検証の考え方 |
| --- | --- | --- |
| NFR-1 | docker コマンドの実行で Neovim の UI をブロックしない | US-013 の受け入れ基準で検証する |
| NFR-2 | 対象 Neovim バージョンは 0.10 以上 | CI で 0.10 と stable のマトリクス実行 |
| NFR-3 | プラグイン由来のジョブ（events / logs / terminal）を残留させない | US-011 の破棄経路・`:qa` の受け入れ基準で検証する |
| NFR-4 | コンテナ 200 件でも一覧の初回描画が体感を損なわない | 大量データでの描画時間を計測（目標値は詳細設計で確定する） |
| NFR-5 | ランタイム依存は外部コマンド `docker` のみとし、Lua ライブラリには依存しない（plenary.nvim は開発時のテスト依存） | 依存の宣言をドキュメントと CI で確認する |
