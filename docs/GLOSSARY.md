# ユビキタス言語 — 用語集

- 種別: 用語集
- 対象: docker.nvim
- 前提ドキュメント: [USECASES.md](USECASES.md), [USER_STORIES.md](USER_STORIES.md)
- 作成日: 2026-07-29

このプロダクトのドメインは「Docker が管理するリソースの状態を、Neovim の中で見て操作すること」である。用語は Docker 側の語彙と、プラグイン内部の語彙の 2 系統に分かれるため、境界づけられたコンテキストごとに整理する。

## コンテキスト一覧

| コンテキスト | 責務 | 外界との接点 |
| --- | --- | --- |
| Docker リソース | docker が管理するリソースの取得・操作・状態変化の受信 | docker CLI / docker compose CLI |
| ビュー表示 | リソースを Neovim のバッファ・ウィンドウに描画し、キー操作を受け付ける | Neovim ランタイム |
| 設定 | 利用者設定とデフォルト設定の合成、キーマップの解決 | 利用者の `setup()` 呼び出し |

同じ語が両コンテキストに現れるものはない。「状態」だけは Docker リソースの状態（running など）とビューの状態（表示中の行・カーソル位置）で意味が異なるため、後者は必ず「ビュー状態」と呼び分ける。

## コンテキスト: Docker リソース

| 用語 | 定義 | 関連用語 | 備考 |
| --- | --- | --- | --- |
| リソース | docker.nvim が一覧表示・操作の対象とするもの。コンテナ・イメージ・ボリューム・ネットワーク・compose サービスの総称 | リソース種別, リソース定義 | プラグイン内部での総称であり docker の公式用語ではない |
| リソース種別 | リソースの分類。`container` / `image` / `volume` / `network` / `service` の 5 種 | リソース, ビュー種別 | 種別ごとに 1 つのビューが対応する |
| コンテナ | docker が実行するプロセスの実体。ID・名前・イメージ・状態・ポート・ラベルを持つ | コンテナ状態, compose ラベル, ポートマッピング | 識別子はコンテナ ID |
| イメージ | コンテナの元になる読み取り専用のテンプレート。リポジトリ名・タグ・ID・サイズを持つ | コンテナ | 識別子はイメージ ID。同一 ID に複数のタグが付き得る |
| ボリューム | コンテナから独立して存在する永続データ領域。名前とドライバを持つ | コンテナ | 識別子はボリューム名 |
| ネットワーク | コンテナ間通信の経路。名前・ドライバ・スコープを持つ | コンテナ | 識別子はネットワーク名。`bridge` / `host` / `none` は削除できない組み込みネットワーク |
| コンテナ状態 | コンテナの実行状況。`running` / `exited` / `paused` / `created` / `restarting` など docker が返す値をそのまま用いる | コンテナ, サービス状態 | 一覧では状態別のハイライトを適用する |
| ポートマッピング | ホスト側のアドレス・ポートとコンテナ側ポートの対応 | コンテナ | ブラウザで開く際、バインドアドレスが `0.0.0.0` / `::` の場合は `localhost` に読み替える |
| compose プロジェクト | 1 つの compose 設定によって管理されるサービス群のまとまり。プロジェクト名で識別する | compose サービス, compose ラベル | 操作対象はカレントディレクトリで解決されるプロジェクトのみ（BR-003） |
| compose サービス | compose 設定で定義された 1 つのサービス。プロジェクト名とサービス名の組で識別する | compose プロジェクト, サービス状態 | 対応するコンテナが存在しないことがある |
| サービス状態 | compose サービスの状況。対応するコンテナがあればそのコンテナ状態、無ければ `none` | コンテナ状態, compose サービス | `none` は「定義はあるが起動していない」を表すプラグイン独自の状態 |
| compose ラベル | コンテナに付与される compose 由来のラベル。`com.docker.compose.project` / `com.docker.compose.service` / `com.docker.compose.oneoff` を使う | コンテナ, compose サービス | コンテナが compose 由来かの判定に用いる（BR-006） |
| 単発コンテナ | `com.docker.compose.oneoff` が真のコンテナ。`docker compose run` などで作られる | compose ラベル, compose サービス | サービスには紐付けない |
| docker イベント | docker デーモンが送出するリソースの状態変化の通知。対象の種別・ID・動作（create / start / stop / destroy など）を含む | イベント購読, ライブ更新 | ライブ更新の入力となる |
| イベント購読 | `docker events` を実行し続け、送出されるイベントを受け取り続けること | docker イベント, ライブ更新 | ビューの表示開始で開始し、破棄で終了する |
| コマンド結果 | docker コマンド 1 回分の実行結果。成否・出力データ・エラーメッセージの 3 つを持つ | docker コマンド実行 | 全ての docker 実行はこの形に正規化して扱う |
| 操作 | リソースに対する状態変更の要求。start / stop / restart / kill / pause / unpause / 削除 / up / down など | 実行中操作, アクション | 「アクション」がキー操作の名前であるのに対し、こちらは docker に対する要求を指す |
| 実行中操作 | 開始済みで完了していない操作。対象と操作の組で記録する | 操作 | 同一対象への同種の操作は同時に 1 つまで（BR-009） |

## コンテキスト: ビュー表示

| 用語 | 定義 | 関連用語 | 備考 |
| --- | --- | --- | --- |
| ビュー | 1 つの画面単位。一覧ビュー・詳細ビュー・ヘルプビューがある | ビュー種別, ビュー状態, ビュースタック | バッファ・ウィンドウとキーマップを伴う |
| ビュー種別 | ビューの分類。リソース種別ごとの一覧（`container_list` など）と、`inspect` / `help` | ビュー, リソース種別 | キーマップとカラムの解決キーになる |
| 一覧ビュー | あるリソース種別のリソースを表形式で並べるビュー | ビュー, カラム定義 | リソース種別ごとに単一のバッファとする（BR-010） |
| 詳細ビュー | 1 つのリソースの inspect 結果を JSON で表示するビュー | ビュー | 一覧ビューから開き、`q` で戻る |
| ヘルプビュー | 現在のビューで有効なキーと説明を並べるビュー | キーマップ | キーマップ定義から自動生成する |
| ビュー状態 | ビューが保持する表示のための情報。表示中のリソース集合・カーソル位置・フィルタ文字列 | ビュー, ビュースタック | Docker リソースの「状態」とは別概念 |
| ビュースタック | 開いたビューの履歴。一覧 → 詳細 → ヘルプ のように積み上がり、`q` で戻る | ビュー, ビュー状態 | 戻ったときにカーソル位置を復元する |
| リソース定義 | リソース種別ごとの宣言的な定義。表示名・取得コマンド・カラム定義・行への変換方法・状態の取り出し方をまとめたもの | カラム定義, リソース種別 | 新しいリソース種別の追加はこの定義の追加で完結させる |
| カラム定義 | 一覧の 1 列の定義。見出しとリソースからの値の取り出し方を持つ | リソース定義, 一覧ビュー | 幅は表示時に内容から決める |
| 行 | 一覧ビューの 1 行。1 つのリソースに対応する | 一覧ビュー, カラム定義 | カーソル行から操作対象のリソースを特定する |
| 描画 | ビュー状態をバッファの内容として書き出すこと | ビュー状態, デバウンス | 状態が唯一の源で、描画はその投影 |
| デバウンス | 短時間に連続する描画要求を最後の 1 回にまとめること | 描画, docker イベント | 連続するイベントでの再描画の暴発を防ぐ |
| ターミナルビュー | ログ追従やシェル起動のために、docker のプロセスを繋いだターミナルバッファ | ジョブ | ビュースタックには積まない（独立したバッファ） |
| ジョブ | プラグインが起動した非同期の子プロセス。イベント購読・ログ追従・ターミナル | イベント購読, ターミナルビュー | ビュー破棄時と Neovim 終了時に必ず終了させる（BR-011） |

## コンテキスト: 設定

| 用語 | 定義 | 関連用語 | 備考 |
| --- | --- | --- | --- |
| 設定 | 利用者が `setup()` に渡す値と、プラグインのデフォルト値を合成した結果 | キーマップ定義 | 利用者が指定しなかった項目はデフォルトが使われる |
| アクション | ビュー上のキーに割り当てられる操作の名前。`start` / `stop` / `inspect` / `refresh` など | キーマップ定義, 操作 | キーとの間に名前の層を挟むことで、利用者はキーだけを差し替えられる |
| キーマップ定義 | ビュー種別ごとの「アクション名 → キーと説明」の対応表 | アクション, ヘルプビュー | ここに無いアクションのキーは設定しない（BR-015） |

## 用語の使い分け

- **操作 と アクション**: docker に対する要求が「操作」、キーに割り当てる名前が「アクション」。1 つのアクションが 1 つの操作を起こすことが多いが、`refresh` のように docker への状態変更を伴わないアクションもある
- **リソース と 行**: docker 側の実体が「リソース」、それを一覧に描画したものが「行」
- **状態 と ビュー状態**: docker が返すリソースの状況が「状態」、ビューが保持する表示情報が「ビュー状態」
- **サービス状態の `none`**: docker には存在しない、プラグインが導入した状態。「compose に定義はあるがコンテナが無い」を表す
